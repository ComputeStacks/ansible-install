# ssh_trust

**Owner:** Wave 1A

Restores control-plane row #4/#19 (docs/contracts.md): the controller
manages tenant registries over SSH (`DockerSSH`) and every node over SSH
(volumes, haproxy cert deploy, LB reload) as root, keyed off two pubkeys
generated on the controller.

## What it does

1. Slurps the controller's root pubkey (`/root/.ssh/id_ed25519.pub`,
   generated by the `common` role) and its app pubkey
   (`/etc/computestacks/.ssh/id_ed25519.pub`). The app key does not exist
   until Wave 3G's controller role creates it — this role `stat`s for it
   first and **warns (does not fail)** and skips installing it when absent,
   so the role is safely rerunnable once Wave 3G lands.
2. Installs both keys as additive `authorized_key` entries into root's
   authorized_keys on every host in `groups['nodes']` **and**
   `groups['registry']`.
3. On the controller, renders `/root/.ssh/config` (whole-file) with a `Host`
   block per node, using inventory vars only (`hostname`, `primary_ip`) —
   **skipped entirely** when the controller is flagged `existing_env: true`
   (attach mode never renders a shared/controller file whole;
   docs/contracts.md rule 9).

## Variables

Consumed, not owned: `groups['controller']`, `groups['nodes']`,
`groups['registry']`, `hostname`/`primary_ip` (node inventory vars),
`existing_env`, `cs_ports.ssh` (`playbooks/group_vars/all/ports.yml`).

## Deviations from v1 (`roles/ssh_transfer`)

- The rendered `/root/.ssh/config` includes a `Host` block **per node only**
  (per Wave 1A instructions). v1 also added `Host` blocks for
  `backup_server`, `metrics`, `registry`, and both nameserver groups — those
  are out of this role's scope for Wave 1A; later waves may extend this
  template if a documented need arises.
- Keys are pushed to `groups['nodes']` and `groups['registry']` only. v1 ran
  `ssh_transfer` against `hosts: all`.
- No "verify controller can connect" smoke-test task — that class of check
  belongs to the `validate` role (Wave 4J), not this role.
